# Журнал решений

Короткие записи о решениях, которые трудно отменить. Новые сверху.
Формат: контекст → решение → последствия. Решение меняем только новой записью, которая отменяет старую.

## D-013 · 2026-11-08 · Прототип собирается генератором

**Контекст:** 68 экранов, правки дизайна должны попадать во все экраны сразу, у каждой цифры должен быть источник.
**Решение:** типовые экраны описываются данными в `docs/ux/style/gen.py` (строки, плитки, шкалы с указанием источника), особые — в `extra.py` и `more.py`. Из тех же описаний генерируется `docs/ux/data-sources.md`. Каждый экран проверяется снимком 800×480 в браузере на той же среде выполнения, что у холста.
**Последствия:** общий компонент правится в одном месте. В M1 библиотека компонентов Slint повторяет эти же типы строк.

## D-012 · 2026-11-08 · Аварийная остановка в одно касание

**Контекст:** внешний ревьюер: «в стоп не нужно подтверждение, он поэтому и стоп».
**Решение:** «Стоп» в меню сразу шлёт `printer.emergency_stop` и показывает экран результата. Защита от случайного касания — опциональное удержание 1 с (Настройки › Безопасность), по умолчанию выключено. Все остальные необратимые действия подтверждаются.

## D-011 · 2026-11-08 · Все функции эталонных экранов, по наличию железа

**Контекст:** владелец: экран будет не только для AD5M, а для любого Klipper; у KlipperScreen, GuppyScreen и HelixScreen базовых функций больше.
**Решение:** берём все функции трёх экранов ([feature-inventory](ux/feature-inventory.md)), у каждой один экран. Экран или строка показывается, только если Klipper/Moonraker сообщает нужный объект или макрос (как chamber air в Helix). Не берём темы, плагины и проверку железа Helix.

## D-010 · 2026-11-08 · Статический musl-бинарь для принтера

**Контекст:** KlipperMod собран на glibc своей версии. Бинарь под glibc хост-системы может не запуститься на прошивке.
**Решение:** target `armv7-unknown-linux-musleabihf`, полностью статический, линкуется встроенным в rustup `rust-lld` (`cargo printer`). Нужную при линковке пустую `libdl.a` генерирует `build.rs`. Шрифты вшиты, fontconfig через dlopen.
**Последствия:** один файл, запускается на любой armv7 Linux независимо от libc прошивки. Собирается на Mac и в CI без внешнего тулчейна. Размер ~8 МБ, из них ~1.25 МБ шрифты.

## D-009 · 2026-11-08 · Свой платформенный слой вместо linuxkms

**Контекст:** в исходниках KlipperMod видно: busybox `mdev` вместо udev, нет libinput и libseat. Тач идёт через tslib (`ts_uinput`), дисплей — `/dev/fb0`. Бэкенд Slint linuxkms требует libinput/libseat (фича `compat-1-2`), так что на прошивке он не заработает.
**Решение:** крейт `fbdev-platform` — реализация `slint::platform::Platform` на чистом Rust: mmap `/dev/fb0`, evdev-тач, цикл событий на `poll`. Логика тача и форматов пикселей вынесена в платформонезависимые модули с тестами.
**Последствия:** никаких системных библиотек. Курсор, клавиатура и DRM не поддерживаются (не нужны). Отменяет вариант «linuxkms + libinput» из D-002.

## D-008 · 2026-11-08 · Не показывать устаревшие данные

**Контекст:** когда Klipper не в `ready`, Moonraker перестаёт слать статусы, а последние значения остаются в памяти.
**Решение:** при любом состоянии, кроме `ready`, и при обрыве связи статус сбрасывается. UI показывает «—» и блокирует действия.
**Последствия:** после shutdown пользователь не видит «печать идёт» и не может нажать бессмысленный Pause.

## D-007 · 2026-11-08 · Название Rivet

**Решение:** проект называется Rivet (заклёпка: маленькая, железная, держит намертво). Бинарь `rivet`, конфиг `rivet.toml`, переменные `RIVET_*`.

## D-006 · 2026-11-08 · Software-рендер везде

**Контекст:** на T113-S3 нет пригодного GPU-стека, а на Mac удобно видеть ровно ту же картинку.
**Решение:** Slint `renderer-software` и на устройстве, и на десктопе (winit).
**Последствия:** пиксель в пиксель одинаково. Ограничения на анимации и эффекты (без размытия).

## D-005 · 2026-11-08 · Два потока: UI и сеть

**Решение:** event loop Slint в главном потоке. Отдельный поток с tokio `current_thread` держит клиента Moonraker и модель. UI → ядро: канал команд. Ядро → UI: снапшот не чаще 10 Гц через `upgrade_in_event_loop`, только при изменениях.
**Последствия:** UI не блокируется сетью, на экране нет лишних перерисовок.

## D-004 · 2026-11-08 · Разработка сначала на Mac

**Решение:** каждая фича сначала работает против `mock-moonraker` и против реального Moonraker по сети. На принтер ставим только с явного согласия владельца.

## D-003 · 2026-11-08 · Первая платформа — KlipperMod

**Контекст:** у KlipperMod нет нормального экрана: KlipperScreen работает поверх Xorg и тормозит, GuppyScreen в alpha и ловит OOM на input shaper.
**Решение:** приоритет AD5M/Pro на KlipperMod, затем Forge-X, remote, AD5X. ZMOD не целевая платформа.

## D-002 · 2026-11-08 · Rust + Slint

**Контекст:** нужен лёгкий нативный UI без X/Wayland на armv7 со 128 МБ.
**Решение:** Rust (stable) + Slint 1.18. LVGL-обёртки для Rust сырые, egui и iced тяжелы для software-рендера.
**Последствия:** один статический бинарь, безопасная работа с памятью, кросс-компиляция через cargo-zigbuild. Риск: linuxkms у Slint требует libinput/libseat (см. роадмап, риски).

**Решение:** публичный open source под GPL-3.0-or-later (совместимо с лицензией Slint GPLv3). Репозиторий приватный до alpha (M2), потом открываем.
