# Регламент строителя экранов

Ты строитель в команде из [ROLES.md](ROLES.md). Твоя задача: довести порученные экраны до вида и поведения
прототипа **один в один** и доказать это инструментом, а не глазами. Владелец отклонял работу за «не похоже на
прототип» много раз: 1:1 — требование, а не пожелание.

## Шаг 0 (обязательно, до всего)
Твоя копия репозитория могла создаться от старого `main`. Выполни в корне копии:
`rm -f tools/compare-prototype.py tools/swap-screen.sh && git reset --hard <ХЕШ, указанный в задаче>`
и убедись, что есть `ui/kit/fills.slint` и `tools/compare-prototype.py`.

## Эталон
`docs/ux/style/<Page>.dc.html` — HTML с инлайн-CSS. Копируй числа дословно: отступы, зазоры, размеры, радиусы,
шрифты, цвета, letter-spacing. Ничего не «улучшай» и не округляй (так уже ломали экран). Общие части — в
`NavRail.dc.html`; токены — `docs/ux/design-code.md`. Значения-примеры из прототипа (имена, температуры,
проценты) воспроизводи в сцене `crates/ui-snapshot/src/main.rs`, но в `.slint`-экранах данные берутся только из
свойств (не зашивай данные прототипа, не выдумывай).

## Как проверять
Статический сервер прототипа уже работает: `http://localhost:8765` (не перезапускай).
```
export CARGO_TARGET_DIR=/Users/i_doc_i/Downloads/rivet-agent-target
python3 tools/compare-prototype.py --proto http://localhost:8765 --out /tmp/cmp-<твоё имя> <сцена> [<сцена> ...]
```
Инструмент рисует наш экран (по-русски) и экран прототипа (headless Chrome), сохраняет
`/tmp/cmp-<имя>/<сцена>.png` как «наш | прототип | разница» (смотри Read) и печатает % различающихся пикселей.
Доводи до ≲1,5 %; остаток должен объясняться (картинки-заглушки, сглаживание). Смотри разницу и увеличенные
фрагменты (Pillow), ищи сдвиги на 1–3 px. Проверяй не только главное состояние: пустой список, 0 %, малое значение,
50 %, 100 %, выбранная вкладка, диалог/клавиатура поверх — всё, что есть в прототипе (добавляй сцены).
Если нет headless Chrome: `CHROME=~/Library/Caches/ms-playwright/chromium_headless_shell-*/chrome-headless-shell-mac-arm64/chrome-headless-shell`.

## Особенности рендера (это не браузер)
- `clip: true` НЕ обрезает по скруглению: заливки — `ui/kit/fills.slint`; углы картинок скругляй в пикселях.
- Обводка `Path` рисуется ВНУТРЬ от линии (SVG — по центру): дугу веди по внешнему краю полосы (см. `ui/kit/dial.slint`).
- На обводке и заливке `Path` нет градиентов: нужен градиент — рисуй кусками.
- Числа в строку команд пути не подставлять (русская локаль даёт `15,9`): только `MoveTo`/`ArcTo`/`LineTo`.
- `for x in m: if c: Foo {}` не компилируется: дели данные на модели или оборачивай.
- `visible: false` место в раскладке занимает.
- Ширины задавай явно из прототипа: предпочтительные размеры Rectangle с текстом отличаются от CSS flex.
- При отпускании пальца отправляется значение, которое выставил палец (показанное уже вернулось к значению принтера).

## Правила владельца
Никаких выдуманных данных (у каждой цифры есть источник Moonraker/Klipper — `docs/ux/data-sources.md`); никаких
технических подписей (G-code, имена API/секций; исключение — консоль, список макросов, сырая ошибка Klipper); одна
система везде (диапазон — вертикальная полоса; подстройка при печати — две ступени; точное число — клавиатура);
никаких мёртвых кнопок (ссылку на ещё не существующий экран не добавляй, а запиши в отчёт); выравнивание важно;
не уменьшай шрифт «чтобы влезло», чини раскладку. Экран или строка только если принтер сообщает нужный объект
(`printer.objects.list`); для любого Klipper, не только AD5M. Все строки через `@tr("English")` + русский в
`i18n/ru/LC_MESSAGES/rivet.po` (`python3 tools/extract-tr.py --check`). Общие компоненты `ui/kit/*` меняй минимально
и перечисли каждое изменение в отчёте; соседние агенты правят другие экраны параллельно.
