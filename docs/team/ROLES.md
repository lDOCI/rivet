# Команда агентов: как строим экраны 1:1

Цель: каждый экран из [каталога](../ux/screen-catalog.md) в Rivet выглядит и работает как в прототипе, для любого
Klipper (D-011). Владелец не ловит баги глазами — это работа ролей ниже. Прототип (`docs/ux/style/*.dc.html`) —
эталон; всё, что отличается, считается ошибкой строителя.

## Конвейер

```
строитель  →  сверщик 1:1  →  контролёр  →  слияние (оркестратор)  →  принтер  →  владелец
   ↑______________ замечания назад к строителю ______________|
```

Строитель не может объявить экран готовым. Экран «готов 1:1» в каталоге ставит только сверщик, «принят» — только
контролёр. Ни один не проверяет собственную работу.

| Роль | Правит код | Решает |
|---|---|---|
| **Строитель** (несколько, параллельно, каждый в своей копии репозитория) | да, только свои экраны | ничего: сдаёт ветку |
| **Сверщик 1:1** (отдельный агент, не видел работы строителя) | нет | PASS / FAIL по каждому экрану и состоянию |
| **Контролёр** (отдельный агент) | нет | APPROVE / CHANGES по правилам и полноте |
| **Оркестратор** (основная сессия) | сводит ветки, заливает на принтер | порядок волн, слияние, что показать владельцу |

## Строитель

Берёт набор экранов (из каталога) и для каждого:
1. Читает страницу прототипа и `data-sources.md`: откуда каждое значение. Нет источника — значения нет на экране.
2. Строит экран из общих компонентов `ui/kit/` (набор строк прототипа: ссылка, информация, переключатель, ползунок,
   шаги, сегменты, кнопки; полосы, шкала, клавиатура, диалог). Новый компонент — только если в прототипе его нет
   в наборе; тогда он идёт в `ui/kit/` и описывается в отчёте.
3. Подключает данные: подписка Moonraker только на то, что есть на принтере (`printer.objects.list`), команды —
   через `Command` в движке, проверка на моке (`mock-moonraker`) и тестом.
4. Копирует числа из CSS прототипа дословно (отступы, размеры, радиусы, шрифты, цвета). Не «улучшает».
5. Добавляет сцену в `ui-snapshot` с теми же данными, что в прототипе, и русские строки в `i18n`.
6. Запускает `tools/compare-prototype.py` и доводит расхождение до порога (ниже), но **не объявляет готовность**.
7. `cargo fmt`, `clippy -D warnings`, `cargo test --workspace`, `tools/extract-tr.py --check`; коммит в свою ветку.

Особенности рендера принтера, которые строитель обязан знать (каждое стоило нам часов):
- `clip` не обрезает по скруглению: заливки — `ui/kit/fills.slint`, углы картинок скругляются в самих пикселях;
- обводка `Path` рисуется внутрь от линии (SVG — по центру): дуги ведутся по внешнему краю полосы;
- на обводке и заливке `Path` нет градиентов: нужен градиент — рисуем кусками;
- числа в строки команд пути не подставлять (русская локаль даёт `15,9`): только `MoveTo` / `ArcTo` / `LineTo`;
- `for … : if …` не компилируется: делить данные на модели или оборачивать;
- `visible: false` место в раскладке занимает;
- при отпускании пальца отправляется значение, которое выставил палец, а не показанное (оно уже вернулось к значению принтера).

## Сверщик 1:1

Независимый агент. Правок кода не делает. Для каждого экрана из пачки:
1. Строит снимки: свой (`ui-snapshot`, русский) и эталон (`tools/compare-prototype.py`).
2. Проверяет **каждое состояние**, которое есть в прототипе: вкладки, выбранные/невыбранные, 0 %, малое значение,
   50 %, 100 %, пустой список, переполнение, диалоги и клавиатура поверх экрана. Для этого строит дополнительные
   сцены; чего нет в прототипе, не придумывает.
3. Смотрит картину «наш | эталон | разница» и увеличенные фрагменты, считает смещения по пикселям.
4. Проверяет поведение: все видимые кнопки работают, нет мёртвых; касания попадают (размеры ≥ как в прототипе),
   значения уходят правильные (по тестам), экран живёт от живых данных, а не от констант.
5. Порог PASS: различающихся пикселей ≤ 1,5 % на каждом состоянии, разница объяснима (картинки-заглушки,
   сглаживание), нет сдвигов контейнеров, шрифтов, радиусов, цветов. Иначе FAIL со списком «что, где, на сколько px».
6. На PASS ставит «готов 1:1» в `screen-catalog.md` и прикладывает снимки в `docs/ux/proofs/`.

## Контролёр

Независимый агент. Правок кода не делает. По диффу ветки строителя проверяет:
- **Источники данных:** у каждой цифры есть источник в Moonraker/Klipper или Rivet; ничего выдуманного
  (пример нарушения: «ещё ~38 с» без измерения скорости нагрева).
- **Для любого Klipper:** экран или строка показываются только если принтер сообщает объект/макрос; нет имён,
  прошитых под AD5M, кроме подписей для известных имён с запасным вариантом.
- **Нет мёртвых кнопок** и ссылок на несуществующие экраны; нет технических подписей (G-code, имена API/секций).
- **Одна система:** переиспользованы компоненты `ui/kit`, нет копипасты, нет «одного шрифта поменьше, чтобы влезло».
- **Безопасность и печать:** опасные действия подтверждаются (кроме аварийной остановки), ничего не отправляется на
  каждый тик перетаскивания, никаких блокирующих операций в потоке интерфейса, бюджеты памяти/CPU из `ROADMAP.md`.
- **Полнота:** каждая функция из `feature-inventory.md` (KlipperScreen, GuppyScreen, HelixScreen), относящаяся к
  экрану, на нём есть либо явно записана как «нет, потому что…».
- **Тесты и язык:** тест на каждую команду, русский каталог полный, документы (`data-sources.md`, каталог) обновлены.
Ответ: APPROVE или CHANGES с нумерованным списком; замечания уходят строителю.

## Оркестратор

Режет работу на волны, запускает строителей, сверщика и контролёра, сводит ветки, прогоняет CI, заливает на
принтер и показывает владельцу только то, что прошло оба шлюза. Владелец проверяет волну на принтере один раз
в конце (см. волны), а не каждый экран.
