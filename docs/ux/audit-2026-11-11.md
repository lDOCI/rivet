# Аудит 2026-11-11: макет против кода, эталоны против макета

Повод: на принтере экраны не похожи на макет, части экранов нет. Владелец спросил, в чём дело.

## 1. Почему код не похож на макет

1. **Две независимые картинки.** Макет описан данными: `docs/ux/style/gen.py` (страницы со строками: ссылка,
   переключатель, ползунок, шаги, сегменты, у каждой строки `src`) и ручные страницы. Slint-экраны написаны
   руками по памяти о макете, без этих данных. При каждом переносе что-то теряется: на «Свете» перенесли
   шкалу и потеряли обе строки-переключателя.
2. **«Готово» значило «компилируется».** Задачи ROADMAP M1 записаны функциями («нагрев», «свет»), а не
   «экран X 1:1». CI проверяет fmt, clippy и тесты, но не внешний вид. Инструмент сверки
   (`tools/compare-prototype.py`) и роли строитель → сверщик → контролёр (`docs/team/ROLES.md`) появились
   11.11, после того как экраны уже были написаны. В отчётах ставилось «готово» без сверки.
3. **Полноту функций никто не сверял с кодом.** `feature-inventory.md` разложил функции по экранам макета, но
   таблицы «функция → экран макета → есть в коде» не было.

соответствующего Slint-компонента (через `i18n/ru`). Совпадение текста не значит совпадение вида — вид

## 4. План: сначала инфраструктура, которая не даёт разойтись, потом экраны

Правило, без исключений: экран «готов» только когда (а) снимок совпадает с макетом по порогу,
(б) каждая строка берёт данные из `data-sources.md` или скрыта, если на принтере этого нет,
(в) есть кадр с принтера (`/dev/fb0`). Без трёх доказательств — не готово, и я так не пишу.

**Этап 0. Макет полный** (владелец, 1 сессия)
- Решение по 16 пунктам раздела 3; принятые дорисовываются в макет; `feature-inventory.md` и каталог обновляются.
- Источник данных для строк без источника (например «Включать при старте» — настройка Rivet, не Klipper).

**Этап 1. Набор компонентов 1:1** (до любых экранов)
- Каждый вид строки макета (`toggle`, `slider`, `link`, `info`, `steps`, `segments`, заголовок раздела,
  основная/вторичная кнопка, плитка, шкала, кольцо) — один компонент в `ui/kit/`, размеры из CSS макета.
- Для каждого — снимок против макета, порог 1,5 %.

**Этап 2. Экраны из данных макета, а не руками**
- 33 страницы макета описаны строками (`ROWS`). Генератор: те же описания → Slint. Структура экрана
  не может разойтись с макетом, потому что они из одного источника. Привязка данных — по `src` строки.
- Ручными остаются уникальные: Главная, Печать, Нагрев, Движение, Файлы, Файл, Z-offset, Состояния.

**Этап 3. Сверка в CI**
- `ui-snapshot` рендерит каждую страницу с данными макета; `compare-prototype.py` сравнивает; CI падает при
  расхождении больше порога. Каталог получает статус «готов 1:1» только отсюда.

**Этап 4. Переделка 22 экранов волнами**
- Волна 1: строчные (Свет, Вентиляторы, Скорость, Подстройка, Ещё, Экструдер, Настройки).
- Волна 2: ручные (Главная, Печать, Нагрев, Движение, Файлы, Файл, Z-offset, Инструменты, Состояния).
- После каждой волны: заливка на принтер, кадры с `/dev/fb0`, показ владельцу.

**Этап 5. 7 недостающих экранов M1**, тем же конвейером. Потом M2.

ROADMAP: задачи M1 переписать с «функций» на «экран 1:1 + доказательства»; изменение — в журнал ROADMAP.

## 5. Пилот 1:1: «Свет» и «Нагрев» (11.11)

Найдено по дороге — причины расхождений, общие для всех экранов:

1. **Сверка не работала.** Эталон рисовался без движка макета (на картинке сырые `{{…}}`), а порог
   «пиксель отличается» был 48 — тёмные карточки (`#15181d` на `#0b0d10`, разница ~13) он не видел:
   «Свет» без двух строк давал 2,5 %. Теперь: эталоны `docs/ux/reference/*.png` и замеры
   `docs/ux/measure/*.json` делает `tools/proto-reference.py` (с движком холста), порог 12.
2. **Шрифты.** Вшиты были только 400/600/700, а 600 не находился вовсе: обрезка шрифта превращала
   SemiBold в отдельное семейство «Inter SemiBold». Весь текст 600 рисовался не тем начертанием,
   800 (заголовки, крупные числа) — заменялся на 700. Теперь 5 начертаний, все — семейство «Inter».
3. **Градиент.** Рендер заливает `Path` одним цветом: шкалы были плоскими. Шкала теперь `Rectangle`.
4. **Сцены снимков не изолированы:** экран получал данные предыдущей сцены. «Нагрев» исправлен,
   остальные сцены задать данными своей страницы макета — в волнах.

Результат (расхождение с макетом, все 21 экран — `tools/compare-prototype.py`):

| Экран | До | После |
|---|---|---|
| Свет | 26,4 % (нет двух строк) | 1,85 % — генерируется из макета (`FormScreen`, `tools/gen-forms.py`) |
| Нагрев | 20,3 % | 5,18 % — по замерам; добавлены ряд «Пресеты · График · PID», время до нагрева |
| Остальные 19 | — | 6–52 %, список в выводе сверки |

Кадры с принтера: `docs/ux/proofs/*-printer.png`; картинки «наш | макет | разница»: `*-compare.png`.

Известные отличия (не ошибки вёрстки):
- Сглаживание текста: Chrome на Mac рисует жирнее, чем рендер Slint (на принтере — Slint). Шум ~1,5–2 %.
- Числа ≥ 32 px: макет в Chrome берёт Inter Display (оптический размер), у нас Inter — «187°» на 6 px уже.
- Точка непрочитанного на «Сообщениях» и ряд «Пресеты · График · PID» на принтере не показываются,
  пока нет данных и экранов за ними (на снимке-сверке ряд включён).

Порог PASS: предлагается 2,5 % + просмотр картинки разницы; ужесточать после Inter Display.
